# CLAUDE.md

CAP 5610 (UCF, Fall 2026) one-person project: classify 250×250 single bone marrow cell images into 21 classes with CNNs. There are two models: a from-scratch baseline CNN and a fine-tuned ImageNet ResNet-50 (EfficientNet-B0 is the fallback). The dataset is HF `ekim15/bone_marrow_cell_dataset` (137k train / 17k val / 17k test). It is already in the local HF cache (`~/.cache/huggingface`). Class imbalance is about 3,700:1 (ABE has 6 train images and 1 each in val/test). The proposal deck `CAP 5610 Project Proposal Presentation.pptx` is the spec: slide 9 covers imbalance, slide 10 the tuning grid, slide 11 evaluation.

## Environment

- Windows 11, RTX 5070 (12 GB, Blackwell), 16 CPU cores.
- Use the venv interpreter `bmenv\Scripts\python` (Python 3.15). Nothing is installed globally.
- torch/torchvision come from the **cu130** index (`--index-url https://download.pytorch.org/whl/cu130`). cu128 has no cp315 wheels, and older CUDA builds don't support Blackwell.

## Commands

```powershell
bmenv\Scripts\python -m pytest -q                                       # unit tests (no dataset/GPU needed)
bmenv\Scripts\python train.py --config configs/resnet50.yaml --smoke     # 1 epoch on ~2k images
bmenv\Scripts\python train.py --config configs/resnet50.yaml --benchmark 50
bmenv\Scripts\python train.py --config configs/baseline.yaml [--set key=value ...]
bmenv\Scripts\python train.py --resume runs/<run>
bmenv\Scripts\python tune.py search --model resnet50 --trials 30 [--smoke]
bmenv\Scripts\python tune.py top --study resnet50_search --k 3
bmenv\Scripts\python tune.py full --study resnet50_search --k 3
bmenv\Scripts\python evaluate.py --checkpoint runs/<run>/best.pt --split validation
bmenv\Scripts\python evaluate.py --compare runs/<a> runs/<b> --split test
```

## Module map

- `preprocess.py`: per-image transforms. Augmentation presets are in `AUG_PRESETS`; the HF `with_transform` hook is `with_preprocessing`.
- `data.py`: label access, stratified subsets, class merge/drop lookup table, class weights, weighted sampler, `make_loader`, `build_data(cfg)`.
- `loader.py`: `BatchLoader`, a multiprocess batch loader (ProcessPoolExecutor, spawn) whose workers never import torch. **Keep torch out of this module.**
- `models.py`: `BaselineCNN`, ResNet-50 / EfficientNet-B0 builders, `set_trainable`, `freeze_bn_stats`, `param_groups`.
- `engine.py`: losses (incl. `FocalLoss`), optimizer and LR schedule, train/eval loops, `fit()` (early stopping + checkpoints), `benchmark()`.
- `metrics.py`: `compute_metrics` (macro-F1 primary) and the plots.
- `cli.py`: `run_and_exit(main)`. Entry scripts end through it because torch 2.14 + Python 3.15 on Windows segfaults (exit 139) at interpreter shutdown after any CUDA conv work. It uses `os._exit` after flushing, so exit codes stay meaningful (0 ok, 1 error).
- `config.py`: the `TrainConfig` dataclass (every tunable field) and typed YAML/`--set` loading.
- `train.py` / `tune.py` / `evaluate.py`: the command-line entry points.
- `class_distribution.py`: EDA chart and counts.
- `check_images.py`: decodes every image (~20 s) and checks `data.CORRUPT_IMAGES` is current. Train row 83795 is corrupt in the HF source itself and is excluded; one undecodable JPEG kills a loader worker and the whole run.
- `configs/`: default configs. `configs/tuned/` is generated by `tune.py top`.

## Rules

- **Never use the test split for tuning or model selection.** Select on validation macro-F1 only. `evaluate.py --split test` runs once per final model; it writes a `TEST_EVALUATED` marker and refuses repeats without `--force`.
- Transform functions must stay **module-level and picklable**, and every script keeps the `if __name__ == "__main__":` guard. Loader workers use `spawn` on Windows.
- **Don't use torch's DataLoader here.** Its workers import torch (~1 GB commit each), and the 12-worker setup ran out of memory at epoch 6 of a full run. Workers that return torch tensors also crash (access violation in torch's shared-memory pickling, torch 2.14 + Python 3.15 on Windows). `loader.BatchLoader` workers import only numpy/PIL/datasets (~0.15 GB, measured) and return uint8 numpy batches. `engine._to_device` makes tensors and runs `preprocess.normalize` on the GPU. Keep `preprocess_image` and `normalize` numerically identical; a test checks this.
- **Entry scripts (`train.py`, `tune.py`, `evaluate.py`, `check_images.py`) import torch/engine/data only inside functions.** Spawned workers re-run the main script's top level. A test asserts workers don't load torch, and workers print a `[warn]` if they do.
- Commit limit is 48 GB (32 GB RAM + 16 GB page file), and other apps use ~28 GB of it. Each run uses `num_workers` train + `num_workers` val workers (default 12 + 12 ≈ 4 GB); `check_worker_memory` warns when it won't fit.
- Measured speed: ResNet-50 @ 224 px trains at ~790–845 img/s (GPU-bound, ~3 min/epoch). The baseline trains at ~1,470 img/s with 12 workers (the loader delivers ~1,850 img/s with `medium` aug). Re-measure with `--benchmark` before changing loader settings.
- Read labels via `data.labels_of()` (Arrow column), never through the transform. Make subsets with `Dataset.select()`. **Never `Dataset.map()` over images**: it rewrites the ~7 GB dataset.
- The `medium` augmentation preset is the original pipeline from the proposal. Don't change it silently; add a new preset instead.
- Run outputs go to `runs/` (gitignored, like `*.pt` and `*.db`). Use `--smoke` for quick checks. **Don't launch long training or tuning runs without asking**: a full ResNet-50 run takes about an hour, and a 30-trial search takes hours.
- Code style: flat modules at the repo root. Each file starts with a docstring explaining what it does, why, and how to run it. Comments explain the reasoning behind non-obvious choices.
